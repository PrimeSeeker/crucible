# What binds in a plan: two sites the statement has not reached

## Observation

Since 2026-11-04 a plan's binding content is its inter-task contracts and each
task's Contract and Acceptance (`crucible:writing-plans § Deferring detail`).
Two sites still read otherwise:

- `skills/subagent-driven-development/references/review-terms.md` § Finding
  scope says a format makes "a plan task's required fields and acceptance"
  binding, and a task's Why and Files are required fields. A plan-phase seat can
  stake a MINOR on one as against binding text, which the fix path then excludes.
  That section's rule, that a required part's absence is a finding, is sound.
- `skills/requesting-code-review/code-reviewer.source.md` flags a departure from
  "binding plan content" as DRIFT, and that seat's template does not say what
  binding plan content is. DRIFT goes to the operator rather than a fix wave.

Neither was exercised on the lane that found them, which has no plan.

## Follow-up

In § Finding scope, say content a format requires, not binding content. In the
drift rule, name the items, as the task reviewer's audit does. Take these with
the next edit in either file.
