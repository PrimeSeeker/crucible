# The unstated-break route: two gaps its last review left

## Observation

`landing-breaks` gave the branch reviewer an `unstated break` label, which goes to the operator as a decision ask (`skills/requesting-code-review/SKILL.md` § The branch-review loop). Its last branch-review pass left two minors, kept here rather than taking another wave, since each matters only when a pass raises the label, which no run has done yet:

- **A pending ask has no carrier.** The operator's answer has a home in the ledger, but the open ask does not: a premise ask is written open under `## Adjudication rulings` and named in the close readout's work left open, and an `unstated break` is neither. An ask lost to compaction or a session break after the terminal pass leaves nothing telling Finish it is pending.
- **The reviewer's report format and verdict line know only the `premise` label.** `skills/requesting-code-review/code-reviewer.source.md` excludes only premise findings from the merge verdict and says only a premise finding's entry opens with its label, so a reviewer staking an `unstated break` at MAJOR would answer "No" on a pass the loop treats as ending the review.
