## Inline mode

You may implement a task yourself only where it is overdetermined (`skills/subagent-driven-development/references/review-terms.md` § The arrangement questions) and fits your remaining context without displacing the coordination state you need through the branch review; otherwise dispatch it, the default.

Review applies unchanged: write your report at the same `sdd/` path, naming each test, case or assertion you deleted or loosened with its justification, as [implementer-prompt.md](../implementer-prompt.md) § Tests: Test-First, Evidence Before Done asks, and dispatch the same reviewer with the same plan pointer, four verdicts and gates. A task the plan marks `Review: branch only` keeps that review when you implement it: the mark applies to a dispatched task. Any loop-entering finding converts the task to standard dispatch, a fresh implementer owning the fixes. Append `Task <N>: inline` where a dispatched task's implementer line goes: every dispute on the task's diff is the adjudicator's, and after a compaction that line still shows the diff is yours.
