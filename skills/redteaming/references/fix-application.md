## Fix application and blind verification

Write the **fix list** into the round record's `## Fix list` (producer: you; consumer: the blind verifier — its *sole* mandate input), then apply it to the artifact. **A fix list takes**, of the findings, BLOCKER and MAJOR ones and **MINORs against binding text**: a MINOR whose fix changes the artifact's own binding content — in a spec what `skills/redteaming/references/flip-paths.md` opens by stating binds, in a plan its Inter-task contracts and a task's required fields and acceptance; a child's fix list never changes umbrella content. Deferral markers, adopted improvements, operator rulings and contained amendments ride it too; other MINORs follow `crucible:redteaming` § Merge and finding hygiene. That holds for every fix list — round 0's, a numbered round's, the plan phase's, the spec terminal pass's follow-up wave's — and for a plan-phase repair. **Fix-by-deletion is a first-class resolution** — a fix that removes machinery outranks one that adds it, all else equal.

**Fix altitude** (binding on every item): a fix states its binding outcome at the altitude of the text around it, in as many sentences as that takes to be unambiguous, and carries no mechanism the surrounding section does not already carry at that level. A deferred finding's item lands that outcome, a `Deferred to implementation:` marker and any acceptance item below; the mechanism is the implementer's to design. **Reproducers travel as acceptance:** where a finding carries a concrete reproducer — an input and the wrong result — and its fix, deferred or landed, changes required behavior, the item adds an acceptance item stating the input and the required result. The outcome and the acceptance item are binding content, which the blind verifier checks like any item and every downstream reviewer grades as binding; the marker's owning task (its placement, or for a spec marker each owning Contract naming it) is only the ownership pointer.

**The artifact states the current design only.** A fix replaces text; it never annotates it. The artifact carries no finding citations, no resolution sketches and no amendment or changelog prose — what changed, in which round, and why live in the round records. The amendment marker a scoped amendment writes — on a shipped spec through SDD, or mid-campaign (`crucible:redteaming` § Flip paths) — is a marker line, not narrative, and stays.

**Propagation sweep — before the list freezes.** A fix edits content, and content is commonly stated in more than one place. For each item, sweep the artifact by the content's key terms for every other site restating what that item changes, and enumerate those sites in the item. Content genuinely stated once yields an item naming its one site and no sweep prose beyond it. A fix that lands at fewer sites than its item names is not landed.

**Trace each rule an item adds or changes — before the list freezes**, a seat's suggested wording included: run `crucible:brainstorming` § Spec self-review's consumer sweep (who produces the rule's input, who reads its output) and trace (which routes and phases reach it) on it, and name each artifact site they find among the item's restating sites. Every fix list and repair named above takes it.

**A predicate is run, not read** (binding). Where an item's substance is a predicate — an acceptance check, a gate, a grep, a census query, any mechanical check — run it at the tree state it will run against before you record the item applied, and put the command and its output under that item in the `## Fix list`. A check of a state the change has not yet reached must fail on today's tree: that failure is the evidence it can fire. A check adopted from a seat's remedy is run the same way — the seat's word is not evidence. Whether the text landed is the verifier's check; whether the predicate is right is yours.

After **every** apply, dispatch the **blind verifier**, instrument `blind-verifier`: inputs are the fix list + the diff **only, never rationale**, with the tracked files a delta claim names as that claim's evidence. It verdicts every item landed or not, checks that nothing outside the list moved, and gives each new "the code does X" claim the wave introduced, a **delta claim**, TRUE or FALSE with evidence, or not checked with the reason (`skills/redteaming/verifier-prompt.md`).

Check each delta claim the verifier reports not checked yourself; record its verdicts, and your outcome for each such claim, in the round record's `## Verifier block` (state `verified`).
